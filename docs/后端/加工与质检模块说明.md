# 加工与质检模块说明

## 模块概述

5 号加工质检模块负责农产品加工环节的链上记录与查询。加工企业（PROCESSOR）在接收农户批次后，对产品进行加工和品质检测，将加工工艺、质检结果、检测报告等信息写入区块链。

---

## 角色与权限

| 角色 | 合约编号 | 说明 |
|------|---------|------|
| PROCESSOR | 2 | 加工企业，可提交加工记录、上传质检报告 |

前端路由前缀：`/processor/*`

## 数据流与状态机

### 合约状态（TraceManager）

| 状态值 | 名称 | 说明 |
|--------|------|------|
| 0 | CREATED | 批次已创建 |
| 1 | FARM_RECORDED | 农事记录已提交 |
| 2 | PROCESS_RECORDED | 加工记录已提交 |
| 3 | LOGISTICS_RECORDED | 物流记录已提交 |
| 4 | RETAIL_RECORDED | 零售记录已提交 |
| 5 | EXPIRED | 已过期 |
| 6 | SOLD | 已售罄 |

加工环节涉及的状态转换：`1 (FARM_RECORDED) → 2 (PROCESS_RECORDED)`

链上前置检查：后端 `_checkStageNotSubmitted` 函数在提交加工记录前会查询链上状态，若当前状态 < 1 则拒绝（前置阶段未完成），若 > 1 则拒绝（已提交）。链不可达时跳过检查，允许继续提交。

### 业务状态映射

合约状态（0-6）通过 `CONTRACT_TO_BUSINESS_STATUS` 映射到业务状态（0-11）：

```js
const CONTRACT_TO_BUSINESS_STATUS = [0, 1, 4, 5, 8, 10, 9];
// 映射: Created(0)→0, FarmRecorded(1)→1(Farming),
//       ProcessRecorded(2)→4(Processed),
//       LogisticsRecorded(3)→5(Transporting),
//       RetailRecorded(4)→8(OnSale),
//       Expired(5)→10(Expired),
//       Sold(6)→9(SoldOut)
```

## 文件上传与验证流程

### 前端流程

```
用户上传文件
    │
    ├─→ 浏览器 crypto.subtle.digest('SHA-256')
    │    → 计算文件哈希 (0x前缀十六进制)
    │    → 存入 localStorage (key: qc_file_hash_{batchId})
    │
    ├─→ 上传文件到服务器 (FormData)
    │    → POST /api/batches/:batchId/upload-file
    │    → serverUploaded = true
    │
    ├─→ 点击"提交哈希上链"
    │    → PUT /api/batches/:batchId/report-hash
    │    → 服务器签名交易写入链上 fileHash
    │    → 显示"哈希已提交"
    │    → hashVerified = true
    │
    ├─→ 点击"链上验真"
    │    → POST /trace/:batchId/verify { fileHash: 0x... }
    │    → 比对链上 fileHash
    │    → 显示"验证通过"或"验证失败"
    │
    └─→ 下载验证证书 (PDF)
         → html2canvas 渲染 DOM → 截图
         → jsPDF addImage 生成 A4 PDF
```

### 侧边栏区块链锚定状态

右侧边栏以时间线形式展示 4 个节点：

| 节点 | 条件 | 状态文字 |
|------|------|---------|
| 1. 文件上传 | `selectedFile` | 等待上传文件 / 文件已上传 |
| 2. 哈希计算 | `hashComputed` | 等待计算哈希 / 哈希已生成 |
| 3. 链上提交 | `hashVerified` | 等待提交 / 哈希已提交(绿) / 提交失败(红) |
| 4. 链上验真 | `verifyResult` | 等待验证 / 验证通过(绿) / 验证失败(红) |

### 验证证书 PDF 内容

```
区块链存证验证证书
✓ 验证通过

批次编号: BATCH_20240521_001
文件哈希: 0xabc...def
验证时间: 2024-05-23 14:30:00 UTC
验证算法: SHA-256
```

生成方式：html2canvas 截取临时 DOM 元素 → jsPDF addImage → 保存为 A4 PDF。

> **前端依赖**：PDF 证书生成依赖 `html2canvas` 和 `jspdf` 两个 npm 包，已在 `package.json` 中添加，运行 `npm install` 即可安装。

### batchController.js 加工提交关键逻辑

```js
// POST /:batchId/process-record
async addProcessRecord(req, res) {
  1. 验证角色是否为 PROCESSOR（processorGuard 中间件）
  2. 从请求体提取 processType, description, reportHash
  3. _checkStageNotSubmitted(batchId, '加工', 1) ← 链上状态检查
     - 链上状态 < 1 → "前置阶段未完成"
     - 链上状态 > 1 → "已提交，不能重复提交"
     - 链不可达 → 跳过，继续
  4. 调用 traceService.addProcessRecord(batchId, ...)
  5. ProcessRecord.create({ batchId, processType, description, ... })
  6. BatchIndex.update({ currentState: 2, fileHash })
  7. 返回 { code: 0, data: { transactionHash, blockNumber } }
}
```

### batchController.js 链上状态检查逻辑

```js
async function _checkStageNotSubmitted(batchId, stageName, expectedState) {
  try {
    const raw = await traceService.getBatchRaw(batchId);
    const currentState = Number(raw?.status ?? -1);
    if (currentState > expectedState)
      throw new Error(`${stageName}记录已提交，不能重复提交`);
    if (currentState < expectedState)
      throw new Error(`前置阶段未完成，无法提交${stageName}记录`);
    return true;
  } catch (err) {
    if (err.message.includes('已提交') || err.message.includes('前置阶段')) throw err;
    // 链不可达时放行
    return true;
  }
}
```

## 注意事项

1. **bytes32 转换**：合约参数为 bytes32 类型，由 `fiscoClient` 自动进行字符串 → bytes32 编码转换
2. **用户签名**：使用登录用户自己的区块链地址签名交易，非系统账户。私钥通过 `getPrivateKey(username)` 获取
3. **合约方法名**：以 ABI 为准 `recordProcessInfo`（不是 `addProcessRecord`）
4. **角色验证**：合约通过 `msg.sender` 查 RoleManager 验证角色是否为 PROCESSOR（编号 2）
5. **表单状态丢失**：路由跳转会销毁组件状态——文件上传和表单数据需在跳转前保存或使用内联操作
6. **本地哈希计算**：SHA-256 在浏览器端通过 `crypto.subtle.digest` 计算，不上传文件内容到第三方
7. **状态不读取缓存**：BatchDetailView 每次 `onMounted` 都重新请求 API，清空 Demo 占位值
8. **链不可达降级**：`_checkStageNotSubmitted` 在链查询失败时放行；链上交易失败时返回 500，不影响 MySQL 写入
9. **farmerStore 集成**：4 号农户模块创建的批次通过 `farmerStore.getBatch` 读取，非农户创建的批次走链上原逻辑
10. **中间件保护**：加工相关路由使用 `processorGuard` 中间件，非 PROCESSOR 角色请求返回 403
