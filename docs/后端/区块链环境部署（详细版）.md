### 智能合约

三个合约需部署至本地 FISCO 节点，ABI 文件位于 `contract_build_info/`：

| 合约 | 地址 | 源码路径 |
|------|------|----------|
| RoleManager | `0x<部署地址>` | `contracts/RoleManager.sol` |
| TraceManager | `0x<部署地址>` | `contracts/TraceManager.sol` |
| AuditManager | `0x<部署地址>` | `contracts/AuditManager.sol` |

ABI 的作用：后端 `fiscoClient.js` 用 `ethers.Interface` 加载 ABI，将函数名和参数编码为合约调用数据，然后发给 WeBASE-Front 的 REST API（`/trans/handle` 写、`/trans/query-transaction` 读），WeBASE-Front 再通过 channel 协议提交给节点。
- `contract_build_info/RoleManager.abi`
- `contract_build_info/TraceManager.abi`
- `contract_build_info/AuditManager.abi`

## 三、环境配置

### 3.1 FISCO 节点管理

```bash
# 进入 WSL
wsl

# 启动节点
cd ~/fisco/nodes/127.0.0.1
bash start_all.sh

# 启动控制台
cd ~/fisco/console
bash console.sh

# 检查节点状态
bash console.sh getBlockNumber
```

> 节点已在 WSL2 Ubuntu 22.04 中运行。确保 Windows 侧能访问 `http://127.0.0.1:8545`。

### 3.2 FISCO BCOS 环境部署

从零搭建 4 节点 FISCO BCOS v2.11.0 单群组链：

```bash
# 1. 安装依赖
sudo apt install -y curl openssl wget

# 2. 下载建链脚本
cd ~ && mkdir -p fisco && cd fisco
curl -#LO https://github.com/FISCO-BCOS/FISCO-BCOS/releases/download/v2.11.0/build_chain.sh
chmod +x build_chain.sh

# 3. 生成 4 节点单群组链
bash build_chain.sh -l "127.0.0.1:4" -p 30300,20200,8545

# 4. 启动节点
bash nodes/127.0.0.1/start_all.sh

# 5. 检查进程
ps -ef | grep -v grep | grep fisco
```

**下载并配置控制台：**

```bash
# 1. 下载控制台
cd ~/fisco
curl -#LO https://github.com/FISCO-BCOS/console/releases/download/v2.11.0/console-2.11.0.tar.gz
tar -xzf console-2.11.0.tar.gz

# 2. 复制证书
cp -r nodes/127.0.0.1/sdk/* console-2.11.0/conf/

# 3. 复制配置文件
cd console-2.11.0
cp conf/config-example.toml conf/config.toml

# 4. 启动控制台验证
bash console.sh
# 控制台内执行 getBlockNumber 应返回 1 或更大
```

若下载缓慢，可选择其他方式（如从已配置好的环境拷贝，或使用代理下载）。

### 3.3 WeBASE-Front 服务

WeBASE-Front 是 FISCO BCOS 的运维管理平台，提供 REST API 来调用合约。后端通过 WeBASE-Front 替代直连节点 RPC，原因：

直连节点 RPC（`http://127.0.0.1:8545`）时**读通写不通**：

- 只读查询（`call`）通过 JSON-RPC 的 `eth_call` 能正常工作，因为 `eth_call` 是 EVM 层面的标准接口，FISCO BCOS 完全兼容
- 写交易（`sendRawTransaction`）走不通，原因在于 FISCO BCOS v2.x 虽兼容 EVM 合约执行，但**交易层 RLP 编码格式与以太坊存在关键差异**：
  - 字段差异：以太坊交易包含 `chainId`、`gasPrice`、`gasLimit`、`nonce`、`to`、`value`、`data`、`v`、`r`、`s`；FISCO BCOS v2 的交易结构不同，ethers.js 构造的 RLP 包会包含 `gasPrice` 等 FISCO 不识别的字段，导致节点解析时报 `invalid Field:gasPrice`
  - 签名机制不同：EIP-155 重放保护签名的编码方式与 FISCO BCOS v2 的签名验证逻辑不完全兼容，导致节点验签失败
  - 节点偏好 channel 协议：FISCO BCOS 节点间通信和交易提交的主通道是基于 AMOP 的 channel 协议（端口 20200），而非 HTTP RPC。WeBASE-Front 通过 channel 协议与节点通信，绕过了 RPC 层的兼容性问题

为便管理，统一改用 WeBASE-Front 的 REST API（`/trans/handle` 写、`/trans/query-transaction` 读），由 WeBASE-Front 负责交易组装、签名和提交。**不要尝试用 RLP 直连节点方式提交交易**。

#### 为何不走 Channel 协议直连 SDK

FISCO BCOS 官方提供了 `@fisco-bcos/nodejs-sdk`，可通过 **Channel 协议**（端口 20200）直连节点，完全绕开 WeBASE-Front 的格式限制。本系统未采用此方案，原因：

1. **WSL2 网络桥接**：FISCO 节点跑在 WSL2 Ubuntu 内，Channel 协议依赖节点 SDK 证书（`ca.crt`、`sdk.crt`、`sdk.key`）直连 20200 端口。后端从 Windows 侧访问 WSL2 的 20200 需额外配置端口转发或桥接网络，增加环境复杂度
2. **私钥集中管理**：当前私钥导入 WeBASE-Front 密钥管理，后端不直接持有私钥。换 SDK 后后端需自己管理私钥文件，安全风险更高
3. **成本收益比**：WeBASE-Front 的"怪脾气"（格式敏感、报文模糊）坑已逐个踩平（见 4.4、4.6 节），当前链路稳定。中途替换 SDK 属于架构级改动，收益（绕过格式限制）远小于成本（重新适配证书/签名/部署流程）

结论：**当前阶段继续使用 WeBASE-Front**。若后期出现复杂 Solidity 参数类型（数组、结构体）导致 WeBASE-Front 解析失败，再考虑切换至 Channel 直连方案。

#### WeBASE-Front 的数据

WeBASE-Front 内部使用 H2 数据库存储自身运营数据（交易记录、密钥信息、区块浏览器缓存），但对本系统而言**它只是一个交易转发层**：

- 业务数据不读写 WeBASE-Front 的内部 DB
- 持久化途径有三条：区块链（链上）、MySQL（业务数据）、本地 JSON 文件（链下缓存）
- WeBASE-Front 宕机不影响已上链的数据，只阻塞新的链上操作

#### 下载与安装

```bash
# 1. 下载 WeBASE-Front v1.5.5（GitHub Releases，网络慢可挂代理）
cd ~/fisco
wget https://github.com/WeBankFinTech/WeBASE-Front/releases/download/v1.5.5/WeBASE-Front.zip

# 2. 解压
unzip WeBASE-Front.zip -d webase-front

# 3. 拷贝节点 SDK 证书（节点运行目录的 sdk/ 子目录）
cp -r ~/fisco/nodes/127.0.0.1/sdk/* ~/fisco/webase-front/conf/

# 4. 确保 Java 11+ 已安装且 JAVA_HOME 已设置
export JAVA_HOME=/usr/lib/jvm/java-11-openjdk-amd64
```

#### 启动

```bash
cd ~/fisco/webase-front
bash start.sh
```

启动后访问 `http://localhost:5002/WeBASE-Front`，可在 Web IDE 中查看和调用合约。

#### 导入私钥（可选项）

WeBASE-Front 的密钥管理用于签名交易。**此步骤为可选项**——当前阶段使用自己的私钥和地址效果一样，只需确保 `.env` 中 `DEPLOYER_PRIVATE_KEY` 与 WeBASE-Front 实际用于签名的私钥一致即可。

如需导入：

1. 访问 `http://localhost:5002/WeBASE-Front` → 密钥管理
2. 导入部署合约时使用的账户私钥

### 3.4 根目录 `.env` 文件

`.env` 已加入 `.gitignore`，不会被提交。首次使用请复制模板并修改：

```bash
cp .env.example .env
```

> 新增配置项时请同时更新 `.env.example`，保持两者一致，方便他人参考。

位置：`项目根目录/.env`

关键配置项：

```ini
# WeBASE-Front API
WEBASE_FRONT_URL=http://127.0.0.1:5002/WeBASE-Front

# 合约地址（填入自己电脑部署后获得的地址）
ROLE_MANAGER_ADDRESS=<RoleManager地址>
TRACE_MANAGER_ADDRESS=<TraceManager地址>
AUDIT_MANAGER_ADDRESS=<AuditManager地址>

# 部署者私钥（填入部署合约时使用的账户私钥，详见 合约部署.md 的"控制台账户管理"）
DEPLOYER_PRIVATE_KEY=填入你的私钥
```

当前 Admin 账户地址即部署合约时使用的账户地址，详见 合约部署.md 的"控制台账户管理"

cd agrichain-backend

后端默认监听 `.env` 中配置的端口（默认 `3001`）。
