# 测试

> ⚠️ **重要：重部署合约后需要更新环境变量**
>
> 每次重新部署合约（更新 `.env` 中的合约地址后），后端进程启动时已加载了旧的环境变量。因此启动后端的终端会话必须加载到新的 `.env`，否则即使重启也仍然读旧地址。
>
> 解决方式：新开终端窗口再 `npm run dev`，或在当前终端重新加载 `.env` 再重启，见下方的 shell 命令。
>
> ```bash
> # 正确流程
> taskkill -f -im node.exe           # Windows / 杀掉所有 node 进程
> npm run dev                         # 重新启动后端（加载新 .env）
> # 新开终端窗口运行测试（确保环境变量一致）
> node tests/e2e_audit.js
> ```
>
> 如果测试终端与后端终端是同一个窗口，重启后端后**必须新开终端**或**重新加载环境变量**再跑测试，否则可能因 PATH / 工作目录不一致导致奇怪失败。
>
> ```bash
> # Git Bash: 从 agrichain-backend 目录重新加载
> cd .. && set -a && source .env && set +a && cd agrichain-backend
> ```
>
> ```powershell
> # PowerShell: 从 agrichain-backend 目录重新加载
> cd ..; Get-Content .env | Where-Object { $_ -match '^[^#].*=' } | ForEach-Object { $k,$v=$_-split'=',2; Set-Item "env:$k" $v }; cd agrichain-backend
> ```

## 前置条件

环境配置请参考相关文档，确保：

- FISCO 节点和 WeBASE-Front 运行正常（见 [`区块链环境部署（详细版）.md`](区块链环境部署（详细版）.md)）
- 智能合约已部署，`.env` 中合约地址和私钥配置正确（见 [`合约部署.md`](合约部署.md)）
- MySQL 服务运行中，`agrichain` 数据库已创建（见 [`后端接入MySQL.md`](后端接入MySQL.md)）
- 后端运行于 `http://127.0.0.1:3001`

> **重新部署合约后推荐清理数据库**：
> 测试已改为每次独立新建批次（`createBatch`），不依赖数据库旧数据，因此旧 `chainBatchId` 不会影响测试结果。但为了保持环境干净，推荐删表重建。
> 
> 清理方法（见《后端上链注意事项》3.2 节）：
> ```sql
> SET FOREIGN_KEY_CHECKS = 0;
> DROP TABLE IF EXISTS batch_index, farm_detail, process_detail, sys_user;
> SET FOREIGN_KEY_CHECKS = 1;
> ```

## 运行命令

```bash
cd agrichain-backend

# 确保后端运行中
npm run dev

# 运行全部测试（Bash / Linux / macOS / Git Bash）
for f in tests/e2e_*.js; do node "$f"; done

# 运行全部测试（PowerShell / Windows）
Get-ChildItem tests/e2e_*.js | ForEach-Object { node $_.FullName }

# 或单独运行
node tests/e2e_auth.js        # 认证
node tests/e2e_farmer.js      # 农户
node tests/e2e_processor.js   # 加工
node tests/e2e_trace.js       # 物流+零售+溯源+审计
node tests/e2e_admin.js       # 管理员
node tests/e2e_upload.js      # 文件上传
node tests/e2e_authz.js       # 角色权限矩阵（推荐先跑）
node tests/e2e_audit.js       # 审计全覆盖
node tests/e2e_verify.js      # 链上+MySQL 验证
```

## API 定义说明

API 由**后端 Express 路由**定义。具体在 `agrichain-backend/src/routes/` 目录下：

| 路由文件 | 前缀 | 定义的操作 |
|---------|------|-----------|
| `routes/auth.js` | `/api/auth` | 登录、注册、个人信息 |
| `routes/admin.js` | `/api/admin` | 用户管理、链信息、合约配置 |
| `routes/batches.js` | `/api/batches` | 批次CRUD、各阶段记录、文件上传 |
| `routes/trace.js` | `/api/trace` | 溯源查询、文件验真、消费者反馈 |
| `routes/audit.js` | `/api/audit` | 审计日志、异常标记、证据链 |

每个路由文件中的 `router.xxx('/path', handler)` 定义了一个 API 端点，`handler` 是对应的 Controller（在 `controllers/` 目录下）。前端 `src/services/api.js` 只是调用方，API 的端点路径、方法、参数、响应格式全部由后端定义。

## transactionHash 提取说明

写操作（审批、停用、加工记录等）的响应中提取交易哈希统一使用 `transactionHash` 字段：

| 提取路径 | 适用 API |
|---------|---------|
| `body.data.transactionHash` | 全部写操作接口（含 `createBatch`、`addFarmRecord`） |
