# 合约部署

## 三、环境配置

### 3.2 合约编译与部署

`.abi` 文件存放在 `contract_build_info/`：

- `RoleManager.abi`
- `TraceManager.abi`
- `AuditManager.abi`

> **规定**：合约使用 Solidity v0.4.25 语法，**须用 solc 0.4.x 编译**（通过 FISCO 控制台）。
>
> **禁止**：不得在项目 `package.json` 中添加 solc 依赖，不得用 `npm install solc` 本地编译，不得用任何脚本临时替换编译器版本。合约编译部署一律走控制台。

#### 控制台账户管理

控制台使用账户签名部署和调用合约，账户 PEM 文件存放在 `~/fisco/console/account/ecdsa/`。部署时使用当前激活的账户，可通过以下命令查看：

```bash
cd ~/fisco/console
bash console.sh listAccount     # 列出所有账户（带 <= 标记的为当前账户）
bash console.sh getCurrentAccount  # 查看当前账户地址
```

**切换部署账户**：如果有私钥（如其他组员交付的密钥文件），可将其导入为控制台账户：

```bash
# 在 WSL 中执行
cd ~/fisco/console

# 用 Python 从私钥生成 PEM 文件（安装 pycryptodome）
pip3 install pycryptodome
python3 << 'EOF'
from cryptography.hazmat.primitives import serialization
from cryptography.hazmat.primitives.asymmetric import ec
from Crypto.Hash import keccak

priv_hex = "这里填私钥（64位十六进制）"
priv_bytes = bytes.fromhex(priv_hex)
priv_key = ec.derive_private_key(int.from_bytes(priv_bytes, "big"), ec.SECP256K1())

pem = priv_key.private_bytes(
    encoding=serialization.Encoding.PEM,
    format=serialization.PrivateFormat.PKCS8,
    encryption_algorithm=serialization.NoEncryption()
)

pub_key = priv_key.public_key()
pub_bytes = pub_key.public_bytes(
    encoding=serialization.Encoding.X962,
    format=serialization.PublicFormat.UncompressedPoint
)
k = keccak.new(digest_bits=256)
k.update(pub_bytes[1:])
addr = "0x" + k.hexdigest()[-40:]

with open(f"account/ecdsa/{addr}.pem", "w") as f:
    f.write(pem.decode())
print(f"账户已导入: {addr}")
EOF
```

导入后运行 `bash console.sh listAccount` 确认新账户出现且为当前账户。

#### 通过 FISCO 控制台部署合约

使用控制台不涉及手动交易签名，部署最稳定：

```bash
# 1. 将源码复制到控制台合约目录
cp contracts/*.sol ~/fisco/console/contracts/solidity/

# 2. 启动控制台
cd ~/fisco/console
bash console.sh

# 3. 部署（先部署 RoleManager，其他合约构造需传入其地址）
[console]: deploy RoleManager
[console]: deploy TraceManager <RoleManager地址>
[console]: deploy AuditManager <RoleManager地址>

# 4. 记录返回的合约地址，更新到 .env 的 *_ADDRESS 字段
# 5. 验证部署
[console]: call RoleManager <RoleManager地址> admin
```

> **脚本模式部署注意**：若使用输入重定向批量部署（如 `java ... console 1 < deploy_cmd.txt`），**必须在指令末尾加 `quit`**，否则控制台会一直等待输入，Java 进程不退出直至超时被 kill。示例：
> ```bash
> cat > /tmp/deploy.txt << INPUT
> deploy contracts/solidity/RoleManager.sol
> deploy contracts/solidity/TraceManager.sol 0x地址
> deploy contracts/solidity/AuditManager.sol 0x地址
> quit
> INPUT
> java ... console.Console 1 < /tmp/deploy.txt
> ```

## 六、重新部署合约完整流程

> ⚠️ **以下步骤按顺序执行，缺一不可。否则合约调用全部 `RevertInstruction (status=0x16)`。**

### 6.1 编译 & 部署合约（WSL 控制台）

```bash
# 进入 WSL
wsl
cd ~/fisco/console

# 复制合约源码
cp /mnt/m/MyTest/working/blockchain/contracts/*.sol contracts/solidity/

# 启动控制台
bash console.sh

# 按依赖顺序部署（先 RoleManager）
[console]: deploy RoleManager
[console]: deploy TraceManager <上一步返回的RoleManager地址>
[console]: deploy AuditManager <上一步返回的RoleManager地址>
[console]: quit
```

> ⚠️ **必记 `quit`**：用脚本/管道（如 `printf`、`echo`、输入重定向）批量部署时，**必须在指令末尾加 `quit`**，否则 Java 进程会一直等待输入不退出，导致后续步骤无法进行。示例：
>
> ```bash
> printf 'deploy RoleManager\ndeploy TraceManager <RoleManager地址>\ndeploy AuditManager <RoleManager地址>\nquit\n' > /tmp/deploy.txt
> java -cp "apps/*:lib/*:conf" console.Console 1 < /tmp/deploy.txt
> ```

记录三个合约返回的地址，下一步要用。

### 6.2 更新 `.env` 合约地址

编辑项目根目录 `.env`，替换三个合约地址：

```ini
ROLE_MANAGER_ADDRESS=0x新地址
TRACE_MANAGER_ADDRESS=0x新地址
AUDIT_MANAGER_ADDRESS=0x新地址
```

如果部署时切换了控制台账户，`DEPLOYER_PRIVATE_KEY` 也要同步换成新账户的私钥。

### 6.3 清理 MySQL 数据库

旧合约的 `chainBatchId` 和用户地址在新合约上无效，推荐删表重建：

```sql
SET FOREIGN_KEY_CHECKS = 0;
DROP TABLE IF EXISTS batch_index, farm_detail, process_detail, sys_user;
SET FOREIGN_KEY_CHECKS = 1;
```

> 不要用 `TRUNCATE`（只清数据不删索引）。多次 `sync({ alter: true })` 累积的索引可能达到 MySQL 上限（64 个），导致 `Too many keys specified`。`DROP TABLE` 等价于删库，但不需重建库。
>
> `sys_user` 存了用户地址，若 RoleManager 重新部署了，需重新 `initUsers()` 授权。DROP 表后重启后端会自动重建并初始化种子用户。

### 6.4 重启后端

```bash
# 杀掉所有 node 进程（Windows）
taskkill -f -im node.exe

# 重新启动（加载新 .env）
cd agrichain-backend
npm run dev
```

观察启动日志，确认出现以下内容：

- `chain self-check PASS`（3 条，分别验证 RoleManager admin、checkRole、TraceManager generateBatchId）
- `数据库表已同步`
- `种子用户已初始化: 6 个`

### 6.5 新开终端窗口运行测试

测试命令详见 [`测试.md`](测试.md)。

> ⚠️ **绝对不要**在启动后端的同一个终端窗口跑测试。必须新开一个终端，或在当前终端重新加载环境变量：
>
> ```bash
> # Git Bash: 从 agrichain-backend 目录重新加载
> cd .. && set -a && source .env && set +a && cd agrichain-backend
> ```
>
> ```powershell
> # PowerShell: 从 agrichain-backend 目录重新加载
> cd ..; Get-Content .env | Where-Object { $_ -match '^[^#].*=' } | ForEach-Object { $k,$v=$_-split'=',2; Set-Item "env:$k" $v }; cd agrichain-backend
> ```
