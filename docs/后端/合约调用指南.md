# 合约调用指南

## 一、合约交互流程

### 1.1 权限初始化

新账户需要先通过 Admin 授权才能使用。有两种方式：

**方式一：后端自动授权（推荐）**

启动后端后，`initUsers()` 会自动为种子用户（如 farmer1、processor1 等）调用合约 `authorizeRole` 授权。只需重启后端即可，无需手动操作。

**方式二：FISCO 控制台手动授权**

```bash
# 在 FISCO 控制台中执行
cd ~/fisco/console
bash console.sh call RoleManager <RoleManager地址> authorizeRole <用户地址> <角色编号> "用户名"
```

角色编号：
- 1: Farmer（农户）
- 2: Processor（加工/质检）
- 3: Logistics（物流）
- 4: Retailer（零售）
- 5: Regulator（监管员）
- 6: Admin（管理员）

### 1.2 加工质检记录上链

后端接口调用 `TraceManager.recordProcessInfo`：

参数：
- `batchId` (bytes32) — 批次 ID
- `processDate` (string) — 加工日期
- `checkResult` (string) — 质检结果
- `fileHash` (string) — 质检报告文件的 SHA-256 哈希

> `fileHash` 应由后端在接收上传文件后计算：`sha256(fileBuffer).digest('hex')`，然后将哈希值传入合约。消费者可通过比对文件本地哈希与链上哈希完成验真。

### 1.3 签名架构

每个用户用自己的区块链地址签名交易，合约通过 `msg.sender` 查 RoleManager 验证角色权限：

```
用户请求 → Controller → traceService → fiscoClient → WeBASE-Front → FISCO BCOS
                    ↓
           req.user.address（JWT 中的链上地址）
                    ↓
           callContractAs(..., signerAddress)
```

#### 角色与合约方法对照

| 用户 | 角色 | 可调用的方法 |
| --- | --- | --- |
| farmer1 | FARMER (1) | `createBatch` |
| processor1 | PROCESSOR (2) | `recordProcessInfo`、`changeBatchState` |
| logistics1 | LOGISTICS (3) | `recordLogisticsInfo`、`changeBatchState` |
| retail1 | RETAIL (4) | `recordRetailInfo`、`changeBatchState` |

> **不要**用单一系统账户签名所有交易。部署者（系统账户）仅用于 bootstrap 授权新用户和管理员操作，写入业务数据必须用对应用户的地址。

### 1.4 fiscoClient 调用注意事项

| 注意点 | 说明 |
| --- | --- |
| 方法名 | 以 `contract_build_info/` 下真实 ABI 为准，**不**信源码假设名（如 `addProcessRecord` 实际是 `recordProcessInfo`） |
| `contractAbi` 格式 | 写接口（`/trans/handle`）传数组 `cfg.abi`；读接口（`/trans/query-transaction`）传字符串 `JSON.stringify(cfg.abi)` |
| `funcParam` 传参 | 写接口（`/trans/handle`）传 `funcParam` 数组（原始参数值），**不传** `encodeStr`。`bytes32` 参数传 hex 编码字符串（如 `ethers.encodeBytes32String("BATCH-001")`），`string` 参数直接传原文。WeBASE-Front 用 Web3j 自行编码函数调用 |
| 地址大小写 | WeBASE 存小写，ethers 生成校验和大小写混合，发请求前必须 `.toLowerCase()` |
| bytes32 参数 | `_convertArgs` 自动将 `string`→`bytes32`（`ethers.encodeBytes32String`） |
| 查询结果 | WeBASE 返回数组 `[val0, val1, ...]`（按 ABI outputs 顺序），用数组下标而非命名属性访问 |
| 空数组检测 | `batchIds(uint256)` 超界限返回 `[]`，`callReadOnly` 对其返回 `null` 以便循环终止 |

### 1.5 只读查询

```javascript
import fiscoClient from './services/fiscoClient.js';

// 查询批次信息
const info = await fiscoClient.callReadOnly('TraceManager', 'getBatchBaseInfo', [batchId]);
// info 为数组 [currentState, farmName, farmOrigin, farmTime, checkResult, fileHash, processTime]
```

### 1.6 写交易参数传递方式

#### 核心原则

`/trans/handle` 不接受预编码的函数数据（`encodeStr`），必须把原始参数值放在 `funcParam` 数组中，由 WeBASE-Front 内部的 Web3j 库自行编码。

#### 参数处理规则

```
bytes32 类型：传 hex 编码的 32 字节字符串
  → ethers.encodeBytes32String("hello")
  → "0x68656c6c6f000000000000000000000000000000000000000000000000000000"

string 类型：传原文即可
  → "2026-05-29" 或 "合格"

uint 类型：传数字或数字字符串
  → 1 或 "1"

address 类型：传小写 hex 地址
  → "0xd79c601f85e2eef2d2b2c4391450937f7afe9b1a"
```

#### 请求体示例

```javascript
// 正确方式：传原始参数 funcParam
{
  contractAbi: abi,
  funcName: "recordProcessInfo",
  funcParam: [
    "0x42415443482d303031000000000000000000000000000000000000000000000000", // bytes32
    "2026-05-29",   // string
    "合格",          // string
    "hash123"       // string
  ]
}
```

#### 后端代码对应关系

`fiscoClient.js` 中的 `_webaseTransact` 方法：

1. 接收原始参数 `args`
2. `_convertArgs` 自动将 `string` 类型的 `bytes32` 参数转为 hex 格式
3. 将转换后的参数放入 `funcParam` 字段
4. 发送给 WeBASE-Front

```javascript
// agrichain-backend/src/services/fiscoClient.js
async _webaseTransact(name, method, args, userAddress, contractCfg) {
  const cfg = contractCfg || contractsConfig[name];
  const body = {
    groupId: this.groupId,
    user: userAddress.toLowerCase(),
    contractName: name,
    funcName: method,
    funcParam: await this._convertArgs(name, method, args), // 原始参数
    contractAddress: cfg.address,
    contractAbi: cfg.abi,   // 数组格式
    useCns: false,
  };
  // POST 到 /trans/handle
}
```

#### 验证方法

用 WeBASE-Front 的 `/trans/encodeFunction` 接口可快速验证 ABI 是否能被正确解析：

```bash
curl -s http://localhost:5002/WeBASE-Front/trans/encodeFunction \
  -X POST -H "Content-Type: application/json" \
  -d '{
    "contractName":"TraceManager",
    "funcName":"recordProcessInfo",
    "contractAbi":<ABI数组>,
    "funcParam":["0x4241...","2026-05-29","合格","hash123"]
  }'
```

返回 hex 编码数据表示 ABI 解析通过；返回 `201151` 表示参数类型不匹配。

## 二、Solidity 合约编写避坑指南

### 2.1 `require` 中 `||` 连接外部合约调用的编译器 bug

Solidity 0.4.25 下，以下写法对有权限的用户会产生 `BadInstruction（0xa）`：

```solidity
// 错误写法：|| 短路求值遇到外部调用时编译器生成错误字节码
require(roleManager.checkRole(msg.sender, 4) || roleManager.checkRole(msg.sender, 5), "No permission");
```

本项目已改为 `onlyRole` 修饰器替代：

```solidity
// 当前使用方案
function changeBatchState(bytes32 _batchId, uint8 _state) public onlyRole(4) {
    require(batches[_batchId].batchId != bytes32(0), "Batch missing");
    batches[_batchId].currentState = _state;
}
```

> 注意：行内对 `bool` 局部变量使用 `||` 是安全的（如 `bool a; bool b; require(a || b)`），不会触发此 bug。
