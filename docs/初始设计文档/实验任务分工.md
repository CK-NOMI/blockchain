全员公共任务
8个人都必须完成：
• 本地链环境安装与运行
• 项目整体业务流程理解
• 能独立讲清楚系统角色、业务链路、上链数据
• 能独立跑通至少 1 次完整演示
• 会回答“为什么用区块链而不是普通数据库”
防止答辩时老师随机点人，一问就不会。

1号：总体架构 / 集成联调 / 主答辩
主责：
总体技术路线
模块划分与进度推进
前后端联调
演示链路统一
最终代码整合
总答辩陈述
副责：
监管端业务逻辑审核
报告统稿

这个人要能讲清楚：
你们为什么选择“农产品供应链溯源”，为什么业务链是这 5 个环节，为什么要做全链路时间线和监管追踪。

2号：区块链环境 / 智能合约 / 上链设计负责人
主责：
区块链环境搭建方案
智能合约设计
上链字段结构设计
批次号生成规则
哈希验真
二维码关联链上查询

重点做需求里明确写到的链上内容：
唯一批次号
农产品名称、品种、产地
播种/采收
质检信息
运输信息与温湿度
上架信息
上链账户地址、操作记录、哈希值。

3号：后端负责人——注册登录 / 角色权限 / 管理员审核
主责：
注册登录模块
角色权限控制
用户身份管理
账号审核
管理员接口
权限隔离

对应需求分析里的：
农户注册与身份认证
管理员账号审核与权限管理
不同角色看到不同功能。

4号：后端负责人——农户模块
主责：
农户录入接口
农产品基础信息管理
种植时间、播种日期
施肥记录、农药使用记录
采收日期、责任人
生成批次号
查看流转状态

5号：后端负责人——加工中心 + 质检模块
主责：
接收农户批次
加工信息录入
清洗方式、包装规格
质检员、检测结果
合格证明
质检报告上传
流转到物流环节

6号：后端负责人——冷链物流 + 超市零售模块
主责：
物流任务接收
车辆编号、司机信息
出发/预计到达时间
冷链温度范围、实时温湿度
运输节点信息
送达确认
超市入库、上架、保质期、货架位置、销售状态
业务链后半段本来就是连续流转，演示时很适合做成一个连贯闭环：
加工完成 → 冷链运输 → 超市入库 → 上架销售。

7号：前端负责人——业务操作端
主责：
农户端页面
加工中心页面
物流页面
超市页面
表单设计
流转状态展示
页面一致性与易用性

8号：前端负责人——消费者溯源页 + 监管端 + 测试文档答辩
主责：
消费者扫码查询页
全链路时间线展示
验证是否上链、是否被篡改
监管员查询页
批次/产地/时间/责任人检索
异常标记与追踪页面
测试报告
答辩PPT
截图整理

需分析中明确提出：
消费者扫码查看完整溯源信息
验证信息是否上链、是否被篡改
监管员按批次、产地、时间、责任人检索与统计
异常标记与追踪。

需求分析中的角色链和流程链：
农户模块 —— 对应农户角色与源头数据
加工模块 —— 对应加工中心和质检报告
物流+超市模块 —— 对应冷链运输、零售上架
消费者+监管模块 —— 对应扫码追溯、异常定位、执法依据
合约模块 —— 对应批次号、关键数据上链、哈希验真


具体8个模块：
区块链环境与合约部署模块
注册登录与角色权限模块
农户信息录入与批次生成模块
加工与质检上链模块
冷链物流信息上链模块
超市入库上架与销售管理模块
消费者扫码溯源与验真模块
监管查询与异常追踪模块
