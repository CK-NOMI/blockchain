《基于 FISCO BCOS 的农产品供应链溯源系统》前端页面完整设计补充版

说明：
本文件是在原“前端设计说明”的基础上，进一步补齐“每个页面具体怎么设计”的内容。重点不是只列页面名称，而是把每个页面的页面定位、布局结构、主要内容、按钮交互、跳转关系、状态反馈、移动端/PC端实现方式都说明清楚，便于后续用 Figma、Stitch、Vue 或 Axure 做页面原型与前端开发。

一、前端总体实现范围

1. 是否同时做 Web 端和手机端

本系统建议采用“PC Web 管理端 + 移动端 H5 查询端”的设计，而不是给所有角色都做手机 App。

（1）PC Web 管理端
面向农户、加工中心、物流企业、超市、管理员、监管员。
这些角色需要登录、填表、上传文件、查看批次列表、查看交易回执、进行监管筛选和审计处理，PC 端更适合复杂表单和表格操作。

（2）移动端 H5 查询端
面向消费者。
消费者不需要进入后台，只需要扫描商品二维码后打开公开溯源页面，查看商品摘要、全链路时间线、质检报告、哈希验真结果和问题反馈入口。

（3）不建议单独开发完整 App
课程项目中不需要单独开发原生 App。消费者端用 H5 页面模拟手机扫码体验即可，既符合真实使用场景，也能控制开发量。

2. 三类前端入口

系统前端最终分为三类入口：

第一类：公共入口
包括登录页、注册页、待审核页、404/403、消费者公开查询页。

第二类：业务操作端
包括农户、加工中心、物流企业、超市四类角色。它们共用统一后台框架，只是菜单和按钮权限不同。

第三类：监管与管理端
包括管理员端和监管端。管理员偏账号、节点、合约配置；监管员偏检索、异常、证据链、审计和风险统计。

二、统一视觉风格设计

1. 整体风格

系统整体采用“蓝白科技风 + 农产品绿色点缀”的可信溯源平台风格。界面应体现“区块链、监管、数据可信、业务闭环”，不要做成普通电商商城，也不要做成农业宣传海报。

视觉关键词：
- 专业
- 清爽
- 可信
- 政务/产业数字化
- 区块链科技感
- 表单和数据清晰可读

2. 主色规范

主蓝色：#1E6EEB
用于顶部导航、主按钮、当前步骤、重要图标。

深蓝色：#173B73
用于页面标题、侧边栏背景、重点文字。

浅蓝色：#EAF3FF
用于卡片背景、提示区域、时间线背景。

绿色：#16A34A
用于已上链、验真通过、正常、完成状态。

橙色：#F97316
用于待处理、预警、临界状态。

红色：#DC2626
用于异常、失败、篡改、过期、审计风险。

灰色：#64748B
用于辅助说明、表格次要字段、禁用状态。

3. PC 管理端通用布局

所有后台页面采用统一框架：

顶部导航栏：
- 左侧：系统 Logo + 系统名称“农产品供应链溯源系统”
- 中间：当前页面面包屑，如“批次管理 / 批次详情”
- 右侧：消息通知、当前用户、角色标签、退出登录

左侧侧边栏：
- 工作台
- 批次管理
- 环节录入
- 数据上链
- 溯源查询
- 预警管理
- 统计分析
- 基础管理
- 系统管理

主内容区：
- 以卡片式布局为主
- 表单页采用“左侧表单 + 右侧状态卡”
- 列表页采用“顶部筛选区 + 中部表格 + 右侧操作区/底部分页”
- 详情页采用“顶部摘要 + 中部时间线 + 下部 Tab 详情”

右侧状态卡：
在业务提交页固定展示：
- 当前状态
- 当前环节
- 上链状态
- 交易哈希
- 上链时间
- 回执状态
- 下一步操作提示

4. 移动端消费者页通用布局

消费者端采用 H5 手机页面风格：

顶部：
- 商品名称
- 返回按钮
- 可信标识，如“放心购”“验真通过”

主体：
- 商品摘要卡
- 当前状态卡
- 全链路时间线
- 附件验真卡
- 交易记录入口

底部：
- 区块链溯源说明
- 问题反馈入口
- 返回查询按钮

消费者页避免展示复杂合约名、节点号、接口参数。技术信息要转化为“已存证”“未篡改”“验真通过”“可追溯”等用户能理解的表达。

四、公共页面详细设计

P01 登录页

页面定位：
系统统一登录入口。所有后台角色从这里进入系统，消费者可通过扫码公开页进入，不强制登录。

页面布局：
左侧为品牌展示区，右侧为登录表单卡片。
左侧可放农田、供应链、区块链节点的轻科技插图。
右侧卡片使用白色圆角卡片，标题为“欢迎登录”。

页面内容：
- 系统 Logo
- 系统名称：农产品供应链溯源系统
- 副标题：基于 FISCO BCOS 的可信追溯平台
- 用户名输入框
- 密码输入框
- 验证码输入框
- 登录按钮
- 注册账号入口
- 消费者查询入口
- 忘记密码入口

按钮与跳转：
- 点击“登录”：校验用户名、密码、验证码。成功后根据角色跳转对应工作台。
  管理员 → /admin/dashboard
  农户 → /farmer/dashboard
  加工中心 → /processor/dashboard
  物流企业 → /logistics/dashboard
  超市 → /retail/dashboard
  监管员 → /regulator/dashboard
- 点击“注册账号”：跳转 /public/register
- 点击“消费者查询”：进入 /public/trace/search 或弹出 BatchID 查询框
- 点击“忘记密码”：弹出“请联系管理员重置密码”的提示

交互细节：
- 登录中按钮显示“登录中…”，并禁用二次点击。
- 用户名或密码为空时，输入框下方提示错误。
- 账号未审核时跳转 /public/pending。
- 账号被禁用时提示“账号已停用，请联系管理员”。
- 角色权限异常时跳转 /common/403。

P02 注册页

页面定位：
让农户、加工中心、物流企业、超市和监管相关用户提交账号申请。

页面布局：
采用三段式表单：
1. 账号信息
2. 主体信息
3. 证明材料

页面内容：
账号信息：
- 用户名
- 密码
- 确认密码
- 联系人
- 手机号
- 邮箱

主体信息：
- 主体类型：农户、加工中心、物流企业、超市零售、监管机构
- 单位名称
- 统一社会信用代码
- 所属地区
- 详细地址
- 申请角色

证明材料：
- 营业执照
- 资质证明
- 身份证明
- 其他补充材料

按钮与跳转：
- “提交注册”：表单校验通过后提交申请，跳转 /public/pending
- “返回登录”：跳转 /public/login
- “重置”：清空当前表单
- “上传材料”：打开文件选择器，上传后展示文件名、大小、上传进度

交互细节：
- 密码和确认密码不一致时提示。
- 手机号格式错误时提示。
- 监管员角色申请需要提示“监管账号需管理员额外审核”。
- 上传材料失败时显示失败原因。

P03 注册待审核页

页面定位：
告知用户注册申请已提交，等待管理员审核。

页面布局：
居中状态卡片。

页面内容：
- 状态图标：待审核
- 申请角色
- 申请单位
- 提交时间

按钮与跳转：
- “返回登录”：跳转 /public/login
- “刷新审核状态”：重新请求审核状态
- 如果已通过，提示“审核已通过，请返回登录”

P04 无权限提示页

十五、最终前端设计总结

本系统前端不需要把每个角色都做成独立 App。更合理的实现方式是：

PC Web 管理端：
农户、加工中心、物流企业、超市、管理员、监管员都使用统一后台框架，通过角色权限控制菜单和按钮。

移动 H5 消费者端：
消费者通过扫码进入公开页面，查看商品摘要、时间线、附件验真和问题反馈。

整个前端的主线是 BatchID。所有批次相关页面都围绕 BatchID 跳转，所有阶段数据都围绕 BatchID 组织，所有消费者查询和监管追责也都从 BatchID 出发。

整个系统的页面设计要服务于三件事：
第一，业务端能够把关键事实按流程提交上链。
第二，消费者端能够把可信结果讲清楚。
第三，监管端能够把异常定位、证据查看和责任追踪做出来。

一句话概括：
本系统前端采用“统一 PC 管理端 + 移动 H5 溯源端”的设计，通过 BatchID 串联角色操作、状态流转、链上存证、附件验真和监管追责，最终形成从生产到消费、从查询到审计的可信溯源闭环。
